# 프레임워크 문서

이 폴더의 문서가 지금의 기준이다. 저장소의 다른 문서와 내용이 다르면 여기 문서를 따른다.

## 지금 기준이 되는 문서

| 문서 | 무엇이 적혀 있나 | 누가 읽나 |
| --- | --- | --- |
| [`/CLAUDE.md`](../../CLAUDE.md) | 작업 규칙. 세 구역, 일하는 순서, 꼭 지킬 규칙, 완료를 말하는 법. | AI 작업자(작업을 시작할 때마다) |
| [`adr/`](adr/README.md) | 결정 기록(ADR). 무엇을 왜 그렇게 정했는지. | AI 작업자, 승인하는 사람 |
| [`glossary.md`](glossary.md) | 용어집. 업무 용어와 코드 이름. | AI 작업자, 승인하는 사람 |
| [`guard-rules.md`](guard-rules.md) | 가드 규칙 G01~G11 의 범위, 예외, 한계. 가드 코드에서 만든다. | AI 작업자 |
| [`ci-gates.md`](ci-gates.md) | CI 가 막는 것, 보호 검사 P1~P5, 예외를 선언하는 법, 승인하는 사람이 볼 것. | 승인하는 사람, AI 작업자 |

`CLAUDE.md` 의 규칙 표와 보호 경로 목록, 그리고 `guard-rules.md` 전체는 가드 코드에서 만들어 넣는다(`node scripts/guard/run.mjs --docs`).
가드와 다르면 `pnpm guard` 가 실패한다. 손으로 고치지 않는다.

## 그 밖의 문서

`docs/` 의 다른 폴더(`admin-platform/`, `hq-standard/`, `multi-market/`, `globalization/`, `operations/`, `rollout/`, `ui/`, `demo/`)와
`docs/` 바로 아래의 단계별 보고서, `spec/` 의 문서는 **지난 작업의 기록**이다.

- 그때 무엇을 만들었고 왜 그랬는지 알아볼 때 읽는다. 지금 따라야 할 규칙으로 읽지 않는다.
- ADR 이 인용한 부분만 지금도 유효하다. 예: ADR 0003 은 `docs/admin-platform/README.md` 의 "임의 SQL·JavaScript·외부 URL 실행은 제공하지 않는다"를 기준으로 삼는다.
- 옛 문서와 이 폴더의 문서가 다르면 이 폴더가 맞다. 옛 문서를 고치지 말고, 필요하면 새 ADR 을 쓴다.
- 옛 문서는 옮기거나 지우지 않는다. 다른 문서와 증빙 자료가 그 경로를 가리키고 있다.

## 명령

| 명령 | 하는 일 |
| --- | --- |
| `pnpm crm classify` | 요청 분류서(유형 A·B·C·D)를 출력한다. 코드를 쓰기 전에 채운다. `--json` 을 붙이면 같은 내용을 자료로 준다. |
| `pnpm crm check` | 가드를 돌린다. 종료 코드는 가드와 같다(0 통과, 1 위반, 2 가드가 돌지 못함). |
| `pnpm crm verify` | 가드(`--strict`), 보호 검사, 가드 테스트, `pnpm build`, `pnpm test`, `pnpm hq:check` 를 차례로 돌린다. 실패해도 끝까지 돈다. |
| `pnpm crm new-object <이름>` | 아직 인자만 검사한다(F1에서 구현). 종료 코드 3. 파일을 만들지 않는다. |
| `pnpm crm add-field <개체> <필드> <종류>` | 아직 인자만 검사한다(F1에서 구현). 종료 코드 3. 종류는 `text`, `decimal`, `date`, `boolean`, `enum`. |

이름 규칙: 개체와 필드 이름은 영어 소문자로 시작하고 소문자·숫자·밑줄만 쓴다. 2~40자. 예: `visit_plan`.

## `pnpm crm verify` 의 증거 꾸러미

`.guard/evidence/<커밋 앞 12자>/` 에 생긴다. `.guard/` 는 git 에 올라가지 않는다.

- `summary.md` : 사람이 읽는 요약. 판정이 맨 위에 있다.
- `evidence.json` : 같은 내용의 자료. 커밋, 브랜치, 커밋하지 않은 변경이 있었는지(`dirty`), 시각, 단계별 명령·종료 코드·걸린 시간·기록 파일, 증거 종류, 판정.
- 단계마다 기록 파일 하나(`01-guard.log` 등).

판정과 종료 코드:

| 판정 | 뜻 | 종료 코드 |
| --- | --- | --- |
| PASS | 여섯 단계가 모두 돌았고 모두 종료 코드 0 이다. | 0 |
| FAIL | 실패한 단계가 있다. | 1 |
| ERROR | 돌지 못한 단계가 있다(명령을 시작하지 못함, 중간에 죽음, 가드 오류, 스크립트가 바뀜, 실행 중 커밋이 바뀜). | 2 |
| INCOMPLETE | 돌리지 않은 단계가 있다. 기준 브랜치(`origin/main`)가 없고 `--base` 도 주지 않으면 보호 검사를 돌리지 못한다. | 2 |

지키는 것과 한계:

- 증거 종류는 언제나 합성(SYNTHETIC)이다. 이 명령은 실제 DB 를 쓰지 않는다. 다른 종류를 적는 옵션이 없다.
- 단계 목록은 코드에 고정되어 있다. 옵션이나 환경 변수로 단계를 빼거나 바꿀 수 없다.
- `pnpm build`, `pnpm test`, `pnpm hq:check` 는 `package.json` 의 스크립트를 돌린다. 그 스크립트가 정해 둔 글자(`scripts/crm/lib/steps.mjs` 의 `PINNED_SCRIPTS`)와
  다르면 그 단계는 돌리지 않고 오류로 적는다. 스크립트를 정당하게 바꿀 때는 그 목록도 함께 바꾼다(보호 경로).
- "알려진 실패" 목록은 없다. 실패하는 테스트가 있으면 판정은 실패다.
- 한계: 증거 파일에는 서명이 없다. 손으로 고친 파일을 구분하지 못한다. 병합 판단에는 CI 가 올린 요약을 쓴다.
- 한계: 이 명령은 그것을 돌린 기기와 그 기기의 `node`, `pnpm`, `git` 을 믿는다. jest·vite 설정을 바꿔 테스트를 빼는 것은 이 명령이 아니라
  보호 검사(P4 보호 파일 변경)와 승인하는 사람이 본다.

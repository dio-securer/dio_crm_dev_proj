# ADR 0002. 세 구역과 이관 대상(legacy) 동결

## 상태

채택 (2026-11-26, F0-4). 구역의 자리와 가드 규칙은 F0-2, F0-3 에서 이미 만들었다. 이 ADR 은 그 결정을 기록한다.

## 맥락

지금까지 화면 하나, 개체 하나마다 코드를 새로 썼다. AI 는 옆에 있는 화면을 복사해 새 화면을 만들고,
"한국만 다르게" 같은 요청에는 그 자리에 조건문을 넣는다. 그렇게 쌓인 코드는 한 곳을 고치면 다른 곳이 깨진다.

## 결정

1. 새 코드와 새 설정은 세 구역 중 하나에 둔다.
   - 설정 구역 `metadata/`: 값만 둔다. 화면, 개체, 필드, 목록, 권한을 값으로 적는다.
   - 엔진 구역 `packages/engine*/`: 설정을 읽어 화면과 API 를 만드는 공통 코드. 회사·국가로 갈라지지 않는다.
   - 확장 구역 `extensions/<이름>/`: 설정으로 표현할 수 없는, 한 회사·국가에만 필요한 코드.
2. 요청은 가장 낮은 구역에서 푼다. 설정으로 되면 설정, 안 되면 엔진에 공통 기능을 넣고, 그래도 안 되는 것만 확장이다.
   분류는 `pnpm crm classify` 의 유형 A·B·C·D 로 한다.
3. 기존의 화면·개체별 코드는 이관 대상(legacy)이다. 목록은 `legacy-files.json` 이다.
   이 목록은 줄어들 수만 있다. 동결된 폴더에는 새 파일을 만들지 않는다. 기존 파일을 고치는 것은 된다.
4. 기존 코드를 한꺼번에 옮기지 않는다. 엔진이 그 일을 대신할 수 있게 된 것부터 하나씩 옮기고 목록에서 뺀다.

## 결과

- 좋은 점: 새 화면이 코드가 아니라 설정으로 늘어난다. 회사별 차이가 한 폴더에 모인다.
- 치르는 값: 엔진은 아직 없다(`packages/engine/` 에는 안내문만 있다). 엔진이 생기기 전에는 유형 B·C 요청을 이 방식으로 풀 수 없다.
- 주의: 동결 구역 밖에 새 폴더를 만들어 화면별 코드를 두는 것은 G10 이 막지 못한다(규칙의 알려진 한계).

## 기계 검사

- G01: `metadata/` 에 설정 파일이 아닌 것을 두면 실패한다.
- G02: 확장이 자기 폴더·계약·엔진 밖을 import 하면 실패한다. 엔진이 `frontend/`, `backend/`, `extensions/`, legacy 계약 파일을 import 하면 실패한다.
- G04: `extensions/` 와 `packages/engine*/` 에서는 코드에 적은 한글 문구를 한 건도 허용하지 않는다.
- G06: `packages/`(엔진 포함), `frontend/src/`, `backend/src/` 에서 회사·국가·시장 값으로 갈라지는 코드가 늘면 실패한다. `extensions/` 는 보지 않는다.
- G07: `extensions/` 와 `packages/` 를 포함한 코드가 DB·네트워크를 직접 부르면 실패한다(허용된 인프라 폴더 제외).
- G10: 동결 구역에 `legacy-files.json` 에 없는 새 파일이 생기면 실패한다.
- P2(보호 검사): PR 이 `legacy-files.json` 에 파일을 추가하거나 분류를 바꾸면 실패한다. 사람이 허락한 경우만 `guard-raises.json` 에 선언한다.
- 아직 기계 검사 없음: "가장 낮은 구역에서 풀었는가"는 기계가 판단하지 못한다. 분류서와 사람 승인으로 본다.

# ADR 0005. 증거 기준: 합성과 실증을 구분하고, 완료는 기계 증거로만 판정한다

## 상태

채택 (2026-11-26, F0-4).

## 맥락

AI 는 "테스트 통과", "완료"라고 쉽게 쓴다. 실제로는 돌리지 않았거나, 일부만 돌렸거나, 가짜 데이터로만 돌린 경우가 섞인다.
승인하는 사람은 코드를 읽지 않으므로 그 말을 확인할 방법이 없다.
또 가짜 데이터로 돌린 검사와 실제 DB·운영 환경에서 확인한 것은 믿을 수 있는 정도가 다르다. 둘을 같은 "통과"로 쓰면 안 된다.

## 결정

1. 증거는 두 종류로 나눠 적는다.
   - 합성(SYNTHETIC): 개발 기기나 CI 에서 가짜 데이터로 돌린 검사. 가드, 단위 테스트, 목업 서버 검사가 여기에 든다.
   - 실증(REAL): 실제 DB 나 운영과 같은 환경에서 확인한 것.
2. 완료는 기계가 만든 증거로만 말한다. 작업자는 `pnpm crm verify` 를 돌리고, 그 증거 꾸러미
   (`.guard/evidence/<커밋 앞 12자>/evidence.json`, `summary.md`)를 근거로 보고한다. 글로만 쓴 "통과"는 증거가 아니다.
3. 돌리지 못한 검사는 통과가 아니다. 오류나 "돌리지 않음"으로 적는다. 실패한 검사를 "원래 실패하던 것"이라며 빼지 않는다.
4. 합성 증거를 실증이라고 쓰지 않는다. 실증이 필요한 일(DB 변경, 운영 배포, 실제 연동)은 실증 증거 없이는 완료가 아니다.
5. PR 을 병합할지는 CI 가 올린 요약으로 판단한다. 작업자 기기에서 만든 증거 꾸러미는 보고의 근거이지 병합의 근거가 아니다.

## 결과

- 좋은 점: "통과"라는 말의 뜻이 하나로 정해진다. 승인하는 사람이 판정 한 줄과 증거 종류만 보면 된다.
- 치르는 값: 지금 실증 증거를 만드는 도구는 없다. 실증이 필요한 일은 사람이 직접 확인하고 그 사실을 적어야 한다.
- 지금 빨간 것: `pnpm test` 에 실패하는 테스트가 1건 있어 `pnpm crm verify` 의 판정은 실패다(`docs/framework/ci-gates.md` 의 "지금 빨간 것").
  이 ADR 에 따라 숨기지 않고 실패로 적는다.

## 기계 검사

- `pnpm crm verify`(`scripts/crm/lib/verify.mjs`): 증거 종류를 상수 `SYNTHETIC` 으로만 적는다. 다른 종류를 적는 옵션이나 코드가 없다.
  단계가 종료 코드 0 으로 끝났을 때만 통과로 적고, 시작하지 못했거나 중간에 죽으면 오류로 적는다. 판정이 통과가 아니면 종료 코드가 0 이 아니다.
  이 동작은 `tests/guard/crm.test.mjs` 가 시험하고, CI 의 "Guard self tests" 단계가 그 테스트를 돌린다.
- 가드와 보호 검사의 결과 파일(`.guard/guard-result.json`, `.guard/protect-result.json`)에도 `evidenceKind: SYNTHETIC` 이 적힌다(`scripts/guard/run.mjs`).
- P3(보호 검사): 테스트를 지우거나 줄여서 통과를 만드는 것을 막는다. G08: 테스트를 꺼 두는 것을 막는다.
- 아직 기계 검사 없음: 보고서나 PR 설명에 글로 "통과", "실증"이라고 쓰는 것은 기계가 확인하지 못한다. 요약을 읽는 사람이 증거 꾸러미와 맞춰 본다.
- 아직 기계 검사 없음 (추가할 단계 미정): 실증 증거를 만들고 검사하는 도구. 증거 꾸러미에 서명이 없어 손으로 고친 파일을 구분하지 못한다.

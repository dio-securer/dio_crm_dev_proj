# ADR 0004. 하위 호환: 지우지 않고 폐기 예정으로 표시한다

## 상태

채택 (2026-11-26, F0-4). 이 결정을 받쳐 줄 설정 형식과 검사는 아직 없다.

## 맥락

설정으로 개체와 필드를 만들면, 그 이름은 저장된 데이터, 목록 설정, 승인 규칙, 보고서, 연동에서 다시 쓰인다.
AI 는 "안 쓰는 것 같다"는 이유로 필드를 지우거나 이름을 바꾼다. 그러면 그 이름을 쓰던 다른 설정과 이미 저장된 데이터가 조용히 깨진다.
법인마다 게시 시점이 달라서, 한 법인에서는 안 쓰는 필드를 다른 법인은 쓰고 있을 수 있다.

## 결정

1. 게시된 개체와 필드는 지우지 않는다. 더 쓰지 않을 것은 "폐기 예정"으로 표시한다.
   폐기 예정인 것은 새로 쓰는 화면에서 숨기지만, 저장된 값과 그것을 읽는 기존 설정은 그대로 동작한다.
2. 이름을 바꿀 때는 옛 이름을 별칭으로 남긴다. 옛 이름으로 들어온 요청과 저장된 데이터는 새 이름으로 읽힌다.
3. 실제 삭제는 따로 승인받는 작업이다. 쓰는 곳이 없다는 증거(ADR 0005)를 붙이고 사람이 승인한다.
4. 필드의 종류를 바꾸는 것(예: 글자에서 숫자로)은 이름 변경이 아니라 새 필드를 만들고 옛 필드를 폐기 예정으로 두는 일이다.
5. 아직 한 번도 게시하지 않은 초안 안에서는 자유롭게 지우고 바꿀 수 있다.

## 결과

- 좋은 점: 설정을 바꿔도 이미 돌아가는 화면과 저장된 데이터가 깨지지 않는다.
- 치르는 값: 폐기 예정 항목이 쌓인다. 주기적으로 3번 절차로 정리해야 한다.
- 지금 있는 것: admin 계약의 확장 필드에는 `active` 값이 있다(`packages/contracts/src/admin/schemas.ts`).
  `active` 를 끄면 그 필드에 쓰는 요청은 `EXTENSION_INACTIVE` 로 거절된다(`packages/contracts/src/admin/security.ts`).
  이것은 "끄기"이지 이 ADR 의 "폐기 예정 표시"와 "별칭"은 아니다. 폐기 예정 표시와 별칭은 미구현이다.

## 기계 검사

- 아직 기계 검사 없음 (F1에서 추가). 지금은 설정에서 필드를 지우거나 이름을 바꿔도 가드가 막지 않는다.
- F1 에서 넣을 것: `pnpm crm add-field` 로 만든 설정을 기준 브랜치와 비교해, 사라진 필드·개체 이름이 있으면 실패하는 검사.
  이 검사는 아직 설계도 코드도 없다. 여기 적은 것은 계획이다.

# F1 단계 보고 — 메타모델

F1 은 "화면·개체를 코드가 아니라 설정 값으로 적는다"의 첫 단계다. 설정의 모양과 검사를 만들었고, 리드 하나를 본보기로 옮겼다.
화면은 아직 이 설정을 읽지 않는다. 운영 동작은 F1 에서 바뀌지 않았다.

## 무엇을 만들었나

| 단위 | 내용 |
| --- | --- |
| F1-1 | 메타모델 검사기 `packages/contracts/src/metadata/` (`validateBundle`, `diffBundles`, `bundleFromFiles`, `filesFromBundle`). admin 의 설정 형식을 그대로 다시 쓴다. 결정은 [ADR 0006](../adr/0006-metamodel.md), 설명은 [metamodel.md](../metamodel.md). |
| F1-2 | 리드 개체를 `metadata/objects/lead/` 로 옮김(필드, 목록 보기, 상태 코드, 두 언어 문구). 검사기를 가드에 연결: G12(형식·참조), P6(기준 대비 하위 호환). |
| F1-3 | 리드를 본보기로 완성: 상세 화면(탭 2, 구역 4), 입력 화면, 목록 보기 2개, 모든 문구 ko-KR·en-US. `metadata/README.md` 에 "리드에 필드 하나 더하기" 안내. P6 테스트 보강. |

## 기계가 검사하는 것

- G12 (`pnpm crm check`): `metadata/` 의 파일 자리, 값의 형식, 닫힌 이름 참조(개체, 필드, 구역·탭, 문구 키, 코드 그룹, 참조 개체, 동작, 기능, 권한, 업무 상태, 상위 메뉴). 검사기를 불러오지 못하면 통과가 아니라 ERROR 다.
- P6 (`--protect`): 기준 커밋에 있던 필드 등을 폐기 예정 표시 없이 지우거나 이름·종류를 바꾸면 실패. 어느 쪽이든 읽지 못하면 실패. P6 위반은 `guard-raises.json` 으로 풀 수 없다(F1-3 에서 테스트로 고정).
- 테스트: `tests/guard/metadata*.test.mjs`(가드 연결, 닫힌 채로 실패), `packages/contracts` 의 메타모델 테스트, 검사 코드 표가 문서와 같은지(`tests/metadata/docs.test.cjs`).

## 아직 검사하지 않는 것

- 열린 이름: 메뉴의 `routeKey`, 확장 필드 `enumValues` 의 값, 승인·알림·번호 등 묶음에 없는 도메인. 틀려도 G12 가 잡지 못한다.
- 런타임: 화면과 서버는 아직 `metadata/` 를 읽지 않는다. 기존 리드 화면은 예전 코드 그대로다. 설정과 실제 화면이 같은지는 확인하지 않음.
- 실제 DB·운영 환경에서의 확인: 하지 않음. 모든 증거는 합성(SYNTHETIC)이다.
- 리드 동작·권한: admin 권한 목록에 리드 권한이 없어 `actions.json` 을 두지 않았다. 권한 목록을 늘리는 일은 F1 밖이다.

## 알려진 문제

- `pnpm crm verify` 의 판정이 PASS 가 아니다. frontend 의 `HqOpportunityList.spec.tsx` 가 F1 이전부터 실패한다. F1 의 변경과는 관계가 없지만, 이것이 고쳐지기 전에는 F1 을 "완료(PASS)"라고 쓸 수 없다.

# 1. 작업 목적

현재 Lead / Account 프로토타입은 A+B 구조의 기본 골격은 구현되어 있으나, 실제 CRM 운영 화면의 기준으로 재사용하기 위해서는 목록 정보밀도, 필터, Detail Header, Mobile 등록 UX, 상태보존, Related Mock 관계 등 공통 기능을 보강해야 한다.

이번 작업의 목적은 **Lead / Account를 A+B 공통 UI Baseline으로 완성**한 뒤, 동일 Component를 Contact / Opportunity / Activity에 재사용할 수 있는 상태로 만드는 것이다.

      ↓

### Mobile

```text

      ↓

      ↓

      ↓

```

## 2.3 이번 작업에서 제외

다음은 본 작업 범위가 아니다.

- Concept C Dashboard 구현
- Concept D Workspace Tabs / Detail Drawer 구현
- 실제 DB Physical Table
- 실제 ERP 연동
- 실제 Backend API 신규 개발
- 실제 권한 서버 연동

> 현재 Mock/Sandbox 구조는 유지하며, 실제 API가 존재하는 화면은 API 실패 시 Sandbox fallback이 동작하도록 유지한다.

# 3. 개발 원칙

## 3.1 기존 Architecture 유지

아래 구조를 깨지 않는다.

- React 19
- 기존 AppShell
- Screen Resolver / Screen Profile
- Market Profile
- Field Section Profile
- i18n
- HQ / GLOBAL 분리 구조
- Mock / Sandbox fallback

화면별로 새로운 독립 구조를 만들지 않는다.

## 3.2 공통 Component 우선

Lead / Account에서 공통으로 필요한 기능은 화면 내부에 중복 작성하지 말고 `frontend/src/ui/ab-workspace/` 아래 공통 Component로 분리한다.

## 3.3 Mock First

현재 목적은 DB 개발이 아니라 UX / 업무 흐름 검증이다.

따라서 아래 기능은 실제 DB 없이 동작해야 한다.

- 신규등록
- 수정
- 검색
- 필터
- Pagination
- Lead 상태변경
- Account 상태변경 Mock
- Contact 추가
- Related Count
- Related Mock List
- Lead → Account Conversion Mock
- ERP Request 상태변경 Mock
- State Preservation

## 3.4 i18n

TSX에 신규 한글/영문 고정 문자열을 직접 작성하지 않는다.

```text
ko-KR
en-US
```

최소 2개 Locale에서 키가 존재해야 한다.

기존 `leadV2.*`는 신규 개발 시 가능한 범위에서 `lead.*` 구조로 통합한다.

## 3.5 Profile

국가별 필드 차이는 Component 내부 `if(country === ...)` 방식으로 처리하지 않는다.

```text
Screen Profile
Field Section Profile
Market Profile
```

기반으로 처리한다.

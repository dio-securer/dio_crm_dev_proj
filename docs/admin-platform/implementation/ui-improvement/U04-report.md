# U04 — 저장·검증·게시

변경한 SCREEN/FIELD 영역을 기존 createDraft/updateDraft로 순차 저장한다. 부분 성공은 성공한 영역만 loaded 기준을 갱신하며 실패 영역 입력은 유지한다. 동일 본문의 응답 유실 재시도에 같은 idempotency key를 유지한다. 관련 7개 domain 초안 목록을 표시하고 미저장·충돌 상태에서는 검증/게시를 차단한다.

검증 전후 원격 초안 revision/내용·부모·게시 버전을 비교하며 10분이 지난 validation은 게시할 수 없다. 게시 확인창은 법인·버전·초안·변경 전후·필수 사유를 표시한다. 409는 기준/내 수정/원격을 비교하고 선택한 변경만 재적용한다. 401/403은 입력 보존 후 편집을 잠근다. 브라우저 이탈, 다시 조회, 고급 설정 이동, 상단 경로 버튼 이동을 보호한다. 기존 법인 전환 저장/폐기/취소 연결을 유지한다.

검증에서 taxId의 서버 잠금 경로가 발견되어 잠긴 셀을 비활성화하고 상태 모델에서도 같은 잠금 경로를 검사하도록 보완했다. 보안 규칙은 변경하지 않았다.

검증: designer-unit 8/8 PASS. 양 모드 UI에서 SCREEN 저장 성공/FIELD 실패 주입→검증 차단→같은 요청 키로 FIELD만 재시도→검증→사유 입력→한 release 게시 PASS. frontend build PASS. 나머지 경합/권한/이탈 세부 인수 항목은 U06/U07에서 추가 실행한다.

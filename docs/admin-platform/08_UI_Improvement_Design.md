# 거래처 화면 설계 UI 개선 설계서
버전: 1.0 · 작성일: 2026-10-22 · 상태: 설계 제안 / 구현 전
대상: feat/admin-platform-a00-a11, PR #28
확인 기준: c16f5b663c7406c57357de44cdf6a4f114faa5b9 및 동일 작업 계열의 AccountDesigner.tsx, SyntheticPreview.tsx, account-runtime.ts.
이 문서의 제안 기능은 현재 구현 완료 기능이 아니다. 기존 A00~A11 완료 기록은 보존한다.
작업 순서·인수 기준: [09 작업지시서](09_UI_Improvement_Instructions.md).

## 1. 문제와 목표
현재 편집기는 드롭다운에서 필드를 한 개씩 선택해 속성을 수정한다. 내부 속성명과 코드가 노출되고, 화면 배치의 결과를 직관적으로 볼 수 없다. 기능 테스트 통과와 현업 사용 편의성은 별도 기준이다.
목표는 전체 필드를 한 화면에서 비교·편집하고, 선택 행을 일괄 변경하며, 적용 전 화면과 변경 차이를 확인하도록 하는 것이다.
기존 계약·상속·권한·초안 revision·검증·게시 경로를 유지한다. UI가 권한이나 필수 항목 제약을 완화해서는 안 된다.

## 2. 범위
| 구분 | 이번 범위 |
|---|---|
| 주 대상 | 거래처 화면 설계: FIELD, SCREEN |
| 보조 대상 | FEATURE, MENU, RULE, LIST_VIEW, ACTION 편집 진입과 저장 상태 통합, 한글 안내 |
| 실제 화면 | 등록된 HQ_ACCOUNT / GLOBAL_ACCOUNT, 법인별 설정 |
| 신규 UI | 그룹 목록, 필드 그리드, 다중 선택, 상세 패널, 합성 화면 미리보기, 변경 검토 |
| 유지 | BROWSER_MOCK / API_MOCK, 기존 route, 기존 업무·권한·게시 엔진 |
| 제외 | 31개 관리자 화면 전면 재설계, 임의 화면 생성, SQL/JS 편집, 실제 DB/ERP/MFA 연결, Excel 가져오기, 타 법인 일괄 배포 |

별도 신규 API 없이 가능한 UI 개편을 우선한다. 그룹 삭제 시 이동과 같은 의존 변경은 여러 설정 문서에 걸치므로 초안 저장의 부분 성공을 명시적으로 다룬다.

## 3. 화면 구성
### 3.1 상단과 하단
상단: 화면 제목, 법인, 등록 화면 유형, 현재 게시 버전, 현재 편집 상태, 도움말.
하단 고정 작업줄: 변경 항목 수 / 초안 저장 / 저장된 설정 검증 / 변경 검토·게시.
게시 버튼은 게시 권한과 최신 검증 결과가 모두 있을 때만 활성화한다. 버튼명과 보조 문구로 현재 저장 범위를 표시한다.

### 3.2 데스크톱 3영역
| 영역 | 기본 폭 | 내용 |
|---|---:|---|
| 왼쪽 | 200px | 전체 필드, 탭·그룹 트리, 필드 수, 그룹 추가·이름 키·열 수·순서 |
| 가운데 | 가변, 최소 560px | 검색, 표시/필수/변경 필터, 필드 편집 그리드, 선택 행 도구 |
| 오른쪽 | 360px | 합성 입력 화면 미리보기, 역할·언어·화면 폭 선택 |
1400px 이상 3영역. 900~1399px는 미리보기를 접이식 패널로 전환한다. 900px 미만은 그룹 선택·필드 목록·미리보기를 탭으로 나누며, 행 상세 편집은 전체 폭 패널로 연다. 작은 화면에서 3영역을 억지로 축소하지 않는다.

### 3.3 필드 그리드
| 열 | 표시/편집 방식 | 규칙 |
|---|---|---|
| 선택 | 체크박스 | 현재 필터 결과만 전체 선택 |
| 항목명 | 번역된 명칭 + 코드 보조 표시 | 코드 불변; 명칭 직접 수정 대신 번역 키 선택/미리보기 |
| 그룹 | 선택 목록 | 존재하는 그룹만 선택 |
| 표시 | 체크박스 | 필수 숨김 검증 적용 |
| 필수 | 체크박스 | 시스템 필수 규칙 유지 |
| 읽기 전용 | 체크박스 | 설정값이며 실제 권한 확대 불가 |
| 순서 | 숫자, 위·아래, 드래그 | 그룹 내 순서; 같은 값이면 key로 안정 정렬 |
| 최대 길이 | 숫자 | 기존 DTO·필드 유형의 범위 검사 |
| 출처/상태 | 배지 | 상속/법인 설정/수정/추가/배치 제거/오류 |
| 상세 | 버튼 | 기본값, 형식, enum, 내부 키, 참조 관계 |
항목명과 labelKey는 구분한다. 이번 버전은 번역 사전 자동 생성·변경을 하지 않는다. 키 미등록이면 원문 키와 경고를 표시하고 번역 관리로 안내한다.

### 3.4 일괄 편집과 선택
- 선택 행의 표시/필수/읽기 전용/그룹 변경을 제공한다. 속성별 유지/예/아니오 3상태이며 기본은 유지다.
- 실행 전 대상 수·변경값·제약 위반 행을 요약한다. 한 행이라도 변경 불가하면 전체 로컬 일괄 동작을 취소하고 해당 행으로 이동한다. 조용히 일부만 적용하지 않는다.
- 검색·그룹 필터 변경 시 선택을 해제하고 알린다. 전체 선택은 전체 데이터가 아닌 현재 필터 결과만 대상으로 한다.
- 단일 셀 편집은 다른 행을 바꾸지 않는다. 선택 행과 변경 행은 별도 상태다.
- 드래그는 검색·필터가 없는 단일 그룹에서만 허용한다. 그룹 내 전체 행을 order 10,20,30…으로 재정렬하고 변경 수를 표시한다. 그룹 이동은 일괄 그룹 변경으로 처리한다.
- 키보드 위·아래 이동은 드래그와 같은 로직을 사용한다.

### 3.5 추가·제거·상세
기존 기본 필드는 key 변경이나 스키마 삭제를 허용하지 않는다. 행 제거는 '화면 배치에서 제거'라고 명시하고 name 등 불변 필수 필드는 차단한다.
확장 필드 추가는 고유 x_ 키, 타입, 번역 키 등을 입력하는 대화상자로 제공한다. 저장 시 extensionDefinitions와 fields를 같은 FIELD 문서에 함께 반영한다.
확장 정의 삭제는 기존 데이터 파괴로 오인되지 않게 설명한다. 첫 버전 UI는 정의의 물리 삭제 대신 비활성화를 제공하며 RULE/VIEW/default 참조를 검사한다. 기존 데이터 마이그레이션은 범위 밖이다.
그룹 제거는 소속 필드가 없을 때만 허용하거나 이동할 대상 그룹을 필수 선택한다. SCREEN/FIELD 양쪽 로컬 변경을 하나의 실행 취소 단위로 기록한다.
상세 패널의 적용은 로컬 작업본만 변경한다. 닫기는 적용 전 입력의 폐기 여부를 확인한다.
기본값은 '미지정'과 빈 문자열/0/false를 구분하고 타입별 입력기로 처리한다.

## 4. 상태와 저장 모델
작업 키: companyId + screenKey + domain + stableKey. 배열 index 대신 field.key / section.id 등 안정 식별자를 사용한다.
- publishedSnapshot: 현재 게시 설정
- loadedDraftSnapshot: 로드 시 effective + 기존 초안을 적용한 작업 기준
- workingCopy: 미저장 사용자 변경
- serverRevisions: draft id/revision, parentVersionIds, currentVersionId
- dirtyPaths, selectedKeys, errorsByPath, undoStack/redoStack, generation
새로고침한 날짜만으로 동시성 판단을 하지 않는다. 늦은 응답은 generation과 회사 키로 배제한다.
실행 취소/다시 실행은 마지막 저장 이후 로컬 변경 최대 50건에 적용한다. 일괄 변경은 1건이다. 서버 저장·게시를 취소하는 기능이 아니다. 저장 성공 영역은 해당 영역 이력을 정리한다.
'편집 취소'는 마지막으로 로드/저장한 초안 상태로 돌아간다. '상속값으로 복원'은 해당 법인 override를 제거하는 별도 동작이며 확인 후 처리한다.
null, false, 0, 빈 문자열, undefined, REMOVE_ITEM의 의미를 기존 changes/resolveOverrides와 동일하게 유지한다. workingCopy를 그대로 전체 덮어쓰기하지 않는다.

## 5. 저장·검증·게시
### 5.1 기존 연결
현재 AccountDesigner.save는 부모 설정 대비 changes를 계산하여 createDraft/updateDraft를 호출한다.
조회: GET /api/admin/config/scopes/COMPANY/{companyId}.
검증: POST /api/admin/config/validate, companyId/draftIds/revisions/expectedReleaseId.
게시: POST /api/admin/companies/{companyId}/releases, validationId/expectedReleaseId/reason.
기존 HttpAdminClient와 DTO를 재사용하고 draft 생성·수정의 실제 endpoint는 client 정의를 따른다.

### 5.2 초안 저장
'변경한 영역 전체 초안 저장'은 dirty domain별로 기존 요청을 순차 실행한다. 서버에 전체 초안을 묶는 원자적 저장 API가 있다고 가정하지 않는다.
예: SCREEN 저장 성공, FIELD 실패 → SCREEN '저장됨', FIELD '저장 실패/입력 유지'. 전체 성공 안내와 게시 활성화 금지.
재시도는 실패 영역만 대상으로 하며 성공 영역의 최신 revision을 사용한다. 동일 요청의 전송 결과가 불확실하면 동일 idempotency key로 재시도하며, 사용자가 payload를 수정하면 새 key를 생성한다.
저장 도중 편집은 잠그고 변경 대상·순서를 고정한다. 부분 저장된 초안은 업무 화면에 적용되지 않는다.
그룹 이동 같은 연관 변경은 둘 다 저장된 뒤에만 검증 가능하다. UI에 '초안 일부 저장, 적용 전'을 표시한다.

### 5.3 검증과 게시
클라이언트 검사는 빠른 안내용이고 기존 서버/공유 엔진 검증이 최종 판단이다. 로컬 미저장·실패·충돌이 있으면 검증/게시 불가.
검증 대상은 현재 화면 설정 관련 저장 초안 전체이며 이름·영역·revision을 사용자에게 보여준다. 다른 탭에서 만든 초안이 포함되면 숨기지 않는다.
게시 전 확인 화면: 법인·현재 버전·대상 영역·필드 변경 전후·적용 영향·사유. 게시 사유 필수.
검증 이후 편집/저장/법인 변경/부모 변경/검증 만료/게시 버전 변경은 검증 상태를 무효화한다.
게시 성공 후 현재 게시 snapshot을 다시 읽고 새 버전을 표시한다. 예약·복원은 기존 설정 운영 화면으로 연결한다.

### 5.4 충돌 및 실패
409: 작업본 보존 → 최신값 별도 조회 → 기준/내 수정/최신값 비교 → 사용자가 항목별 재적용 결정 → 새 revision으로 저장·재검증. 자동 덮어쓰기 금지.
422: 필드 key와 속성별 오류 연결, 오류 요약 클릭 시 필터를 조정해 해당 셀에 포커스.
403/세션 만료: 편집·게시 중지, 저장되지 않은 입력은 해당 화면 메모리에 보존. 재인증 후 같은 법인/권한 재검사. 민감값을 새 localStorage에 저장하지 않는다.
다시 조회·법인 전환·화면 유형 전환·라우트 이동에 미저장 변경이 있으면 저장 후 이동/폐기 후 이동/취소. 저장 실패 시 이동하지 않는다.
탭 닫기는 beforeunload 경고를 사용하며 브라우저 강제 종료 후 미저장 복구를 보장하지 않는다.

## 6. 화면 미리보기
기존 SyntheticPreview는 JSON 결과 중심이다. 입력 폼 형태의 새 AccountFormPreview를 제공하고 기존 진단 결과는 고급 정보로 접는다.
입력은 workingCopy와 합성 데이터이며 업무 조회/저장·승인·ERP 요청을 발생시키지 않는다. '미저장 작업본 미리보기, 실제 적용 전'을 표시한다.
기존 effectiveFields / fieldDefinitions / 권한 평가 / 메뉴 feature 평가를 공유한다. 별도 규칙 엔진을 복제하지 않는다.
현재 게시본 / 작업본을 전환하여 비교한다. 역할·ko/en·데스크톱/모바일·샘플 조건을 선택할 수 있다.
샘플 역할은 시뮬레이션이지 실제 사용자 권한 획득이 아니다. 실제 업무 원문 데이터나 마스킹 원문은 불러오지 않는다.
오류 작업본은 '미리보기 불가'와 해당 셀을 안내한다. 이전 정상 화면을 그대로 최신 미리보기로 보여주지 않는다.
권한·규칙·설정이 겹친 결과는 숨김/읽기 전용 사유를 진단 영역에서 설명한다. 미리보기 결과를 게시 검증 PASS로 취급하지 않는다.

## 7. 접근성·사용성
일반 table과 명시적 label/input을 기본으로 한다. Enter 편집/확정, Escape 현재 셀 취소, Tab 이동을 제공하고 방향키를 숫자 입력기의 기본 동작과 충돌시키지 않는다.
행 이동 버튼과 상세창 초점 복귀를 제공한다. 체크박스는 항목명+속성을 접근성 이름으로 갖는다.
수정·오류는 색상 외 텍스트/아이콘으로 구분한다. 에러/저장 결과는 live region으로 알린다.
영문 속성명은 한국어 명칭으로 표시하고 ko/en locale 리소스를 사용한다. 업무 필드명과 편집기 UI 번역은 별도로 유지한다.
100개 필드를 기준으로 일반 렌더링을 먼저 측정한다. 가상 스크롤 도입은 키보드·오류 이동이 유지될 때만 허용한다.

## 8. 완료 기준과 제한
09의 UAT 전부 PASS, BROWSER_MOCK/API_MOCK 동일 결과, 기존 A05/A10 권한·게시 회귀 통과가 완료 조건이다.
문서 작성 완료, UI 구현 완료, 실제 사용자 검토 완료를 구분한다. 실제 현업 명칭·업무 규칙 변경은 이 UI 개편에서 자동 확정하지 않는다.

# A09 실행 지시 — ERP 연동 가정 구현

상태의 단일 원본: [queue.json](queue.json). 선행: A08. 대상: ADM-24~25.

## 실행 입력

[공통 실행 규칙](README.md)을 먼저 읽고 원격 최신 브랜치와 선행 완료 보고서를 확인한다. 확정 요구는 상위 README 및 01~07 원문이며 이 파일은 실행 단위로 풀어 쓴 체크리스트다. 원문 요구를 삭제하거나 축소하지 않는다.

## 구현 체크리스트

- [ ] 기존 interfaceCode, account/contract/order 결과 핸들러 및 enqueuePending을 먼저 조사하여 adapter-map을 보완한다.
- [ ] ERP profile·mapping typed 관리, MOCK 표시, payload preview 및 미등록 interface/필수 mapping/LIVE 선택 거부를 구현한다. 미리보기는 요청을 생성하지 않는다.
- [ ] 04 §7의 7 transport 시나리오 전체와 §9.4 경합 규칙을 구현한다. business request와 attempt/version을 분리하고 businessOutcome을 transport 상태와 분리한다.
- [ ] 거래처 실제 UI에 ERP 요청→모의 승인/반려→상태 갱신을 연결한다. 계약/주문/수금/납품은 합성 fixture 기반 관리 시연으로 제공한다.
- [ ] 실패 후 retry, timeout late response, duplicate, out-of-order, 타 회사 응답, 같은 key의 payload hash 충돌 및 같은 version 다른 payload를 검증한다.
- [ ] 수금 정정은 최신 version의 교체 합계로 반영하고 중복 가산을 막는다. 대체된 요청 응답은 stale로 남기며 모든 attempt 이력을 조회한다.
- [ ] 로그에서 mode/scenario/businessOutcome/attempt/requestId를 조회한다. mode=MOCK일 때만 결과를 적용하며 기존 enqueuePending을 전역 자동 성공으로 바꾸지 않는다.

- [ ] 모의 ERP 성공/실패 이벤트를 A08 outbox에 연결하여 대상 수신자의 알림과 중복 제거를 통합 검증한다. 외부 EMAIL 전송은 0건을 유지한다.

## 검증과 완료 조건

필수 인수 항목: **T18~T24,T53,T54,T80**. 각 기대값·모드는 06 원문을 그대로 따른다. 공통 gate와 기존 기능 회귀를 포함한다.

기존 domain handler 또는 명시된 sample handler가 업무 상태를 정확히 1회 변경하며 실제 ERP egress가 0이다.

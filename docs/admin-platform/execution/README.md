# A07~A11 실행 대기열과 재개 규칙

2026-10-21 · 사용자 승인: 남은 단계를 GitHub에 각각 등록하고, 이후 채팅 호출 시 지시서를 가져와 단계별 세부 지시 없이 수행한다.

## 시작 방법

이 저장소에서 **“남은 단계 계속 진행”**, **“A07~A11 진행”**이라고 호출하면 아래 대기열의 첫 미완료 단계부터 마지막까지 순차 실행한다. **“다음 단계만 진행”** 또는 특정 단계만 지정하면 그 범위만 수행한다. 파일 내용을 다시 붙여넣거나 매 단계 구현·테스트·B 검토·PR 반영을 따로 지시할 필요가 없다.

이 문서는 실행 예약/백그라운드 서비스가 아니다. 채팅에서 실행을 호출한 동안 진행하며, 세션 중단·도구 제한으로 멈춘 경우 다음 호출에서 checkpoint로 재개한다. 현재 등록은 실행 계획이며 A07~A11 구현 완료를 뜻하지 않는다.

## 실행자 필수 순서

1. `docs/admin-platform/README.md`, 01~07 확정 설계, queue.json, 해당 단계 지시서, 선행 보고서를 읽는다. 현재 원격 브랜치/PR, 로컬 미커밋 변경과 코드 상태를 확인한다. 기존 작업을 덮어쓰지 않는다.
2. queue에서 첫 미완료 단계와 실제 보고서·커밋을 대조한다. PENDING/IN_PROGRESS/BLOCKED/REVIEW 단계는 완료로 건너뛰지 않는다. 선행이 DONE이고 증거가 있을 때만 다음 단계로 간다.
3. 단계 상태를 IN_PROGRESS로 바꾸고 실제 메뉴·typed 화면·이벤트·API·저장·권한·오류 처리를 구현한다. 필요한 일상적 구현 선택은 실행자가 판단한다. 사용자에게 이미 승인된 세부 작업을 다시 허락받지 않는다.
4. 단위·실제 ephemeral HTTP·양 모드 브라우저와 필요한 회귀 테스트를 실행한다. 새 명령은 package.json에 등록한 뒤 사용한다. fake clock을 사용하고 외부 ERP/EMAIL egress0을 확인한다. 실제 실행하지 않은 테스트는 PASS로 기록하지 않는다.
5. 작업자 B에게 코드와 증거를 독립 검토시킨다. 기존 worker B가 있으면 재사용하며 새 세션이면 B 검토자를 구성한다. 이는 기존 사용자가 요청한 B 재검증 흐름이다. 차단 지적은 수정→관련 재검증→B 재검토까지 해결한다. B 사용 불가 시 승인했다고 쓰지 않고 REVIEW와 사유를 남긴다.
6. 보고서·로그·캡처·인수 결과를 작성하고 코드와 함께 GitHub에 커밋한다. 원격 head를 확인하고 충돌 시 보존·병합한다. 강제 덮어쓰기를 하지 않는다. 기존 PR은 초안으로 유지한다.
7. 필수 테스트 PASS, B 승인 및 원격 반영 확인 후 queue의 단계를 DONE으로 갱신한다. report/evidence/review에 실제 경로와 검토 결과를 기록하고 nextStage를 다음 미완료 단계로 변경해 GitHub에 저장한다. 같은 커밋의 자기 SHA를 억지로 넣지 않고 보고서의 검증 기준 커밋과 Git 이력으로 추적한다.
8. “남은 단계 계속” 호출이면 별도 승인 질문 없이 다음 단계로 이어간다. 완료된 단계마다 짧은 진행 현황을 알리고, A11까지 끝나면 전체 결과와 실제 남은 제한을 보고한다.

## 중단과 재개

status는 PENDING / IN_PROGRESS / REVIEW / BLOCKED / DONE을 사용한다. checkpoint에는 다음을 기록한다.

- 기준 commit, 변경 파일, 현재 구현 위치
- 마지막 성공 테스트 명령과 로그, 실패/미실행 항목
- 미해결 B 지적, 중단 사유, 다음 실행 명령
- datasetId/schemaVersion, 환경 및 증거 위치

중단 전 가능한 작업은 GitHub에 저장한다. 업로드가 실패하면 성공으로 표시하지 않고 로컬 위치와 장애를 보고한다. 재개 시 최신 원격 checkpoint를 읽고 실제 파일·테스트 결과와 대조한다. 코드가 바뀌면 필요한 검증을 재실행한다. 외부 접근/도구 차단 등 실제 해결 불가 사유만 사용자에게 질문하며, 불필요한 단계별 확인으로 멈추지 않는다.

## 범위와 완료 판정

- 단계 간 통합 의존성은 UNIT/INTEGRATION 증거로 분리한다. T13은 A07 결정·이벤트 UNIT과 A08 알림 INTEGRATION, ERP 알림은 A08 계약과 A09 연결로 나눈다. 선행 단계 DONE은 명시된 해당 단계 범위 완료이며, 통합 미완료 TC 전체를 PASS로 바꾸지 않는다.
- 원문 05와 06 v1.3(P2 반영)가 기준이며 이 실행 파일은 이를 대체하지 않는다. T01~T83 및 31 ADM 대응표를 유지한다.
- A06까지의 기능·원본 데이터·LEGACY 경로를 보존한다. 선행 회귀가 깨지면 복구한 뒤 진행한다.
- 실제 ERP/EMAIL/SSO/TOTP, 운영 DB migration·배포는 범위 밖이다. A10은 DEMO SECURITY 정책 게시 통합을 포함하되 실제 OTP 연동 완료로 주장하지 않는다.
- main 병합 및 운영 배포는 이 대기열에 포함하지 않는다. PR #28 초안에서 검토 가능한 결과를 완성한다.
- 필수 FAIL/BLOCKED가 있으면 전체 완료를 선언하지 않는다. A11 인수 결과에 누락 없이 기록한다.

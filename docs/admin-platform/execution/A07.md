# A07 실행 지시 — 프로세스 정의·승인 엔진·관리 화면

상태의 단일 원본: [queue.json](queue.json). 선행: A06. 대상: ADM-19~22.

## 실행 입력

[공통 실행 규칙](README.md)을 먼저 읽고 원격 최신 브랜치와 선행 완료 보고서를 확인한다. 확정 요구는 상위 README 및 01~07 원문이며 이 파일은 실행 단위로 풀어 쓴 체크리스트다. 원문 요구를 삭제하거나 축소하지 않는다.

## 구현 체크리스트

- [ ] 상태·전이, 승인 정책, 결재선의 typed 관리 화면을 구현하고 초안·검증·게시와 연결한다. 시작 상태 중복, 도달 불가 상태, 불법 전이를 검증한다.
- [ ] APPROVAL_DEMO_DOCUMENT CRUD/제출, 일반 사용자 승인함, instance/task/event를 연결한다. 작성자→배정자 계정 전환으로 실제 업무 상태 변화를 검증한다.
- [ ] 순차/병렬 ANY·ALL, 승인·반려·회수·수정·재상신을 04의 집계 규칙대로 구현한다. revision, idempotency, 원자적 이벤트를 적용한다.
- [ ] 제출 시 문서 revision·정의·정책·결재선·달력/timezone·dueAt snapshot을 고정한다. A06 영업일 엔진을 재사용하고 설정 변경 후 기존 건 불변을 검증한다.
- [ ] 자기승인·빈 승인자·동순위 정책 충돌·미확정 GLOBAL route를 거부한다. 승인자 활성 상태를 결정 시 재검사하고 BLOCKED/권한 있는 강제 재배정과 이력을 연결한다.
- [ ] 대결 저장·조회·등록·회수, 기간 경계, 겹침·연쇄·자기대결 거부 및 원승인자/실결정자 이력을 구현한다. 동시결정·대결 회수 경합을 검사한다.
- [ ] 기존 activity route는 legacy adapter로 유지하고 새 엔진 feature가 켜진 문서만 적용한다. 목업 route에는 DEMO_ONLY를 표시한다.
- [ ] A08이 소비할 승인/반려/기한 이벤트 계약과 저장 기반을 준비한다. 알림 전달 완료는 A08 검증 전 주장하지 않는다.

## 검증과 완료 조건

필수 인수 항목: **T12~T17,T31,T52,T64,T65,T76~T78**. T13은 A07에서 결정 중복/멱등성과 이벤트·outbox 생성 UNIT을 검증하고, 알림 1회 전달 INTEGRATION은 A08에서 검증한다. A07 완료는 이 UNIT 범위를 기준으로 하며 최종 T13 PASS는 두 수준이 모두 통과한 후 기록한다. 각 기대값·모드는 06 원문을 그대로 따른다. 공통 gate와 기존 기능 회귀를 포함한다.

단계 그림만이 아니라 문서 상태·승인함·대결·이력이 양 모드에서 동작하고 필수 경합/권한 HTTP 검증을 통과한다.
